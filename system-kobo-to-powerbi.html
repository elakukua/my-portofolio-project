STEP 01
↓
Form design

The form is the first and cheapest data quality control. Every constraint added here is a cleaning task avoided later.

Process
  • Question wording tested with enumerators in the field language before deployment
  • Constraints and skip logic so impossible or contradictory answers cannot be submitted
  • Choice lists rather than free text wherever a category exists
  • Required fields limited to what is genuinely required — over-forcing produces false answers
  • GPS, photo and timestamp capture where verification will be needed
Output
  • A deployed form that produces analysable data, not a transcript needing interpretation
STEP 02
↓
Enumerator setup and training

A well-designed form still fails if the people using it count differently.

Process
  • Train on the indicator counting rules and the form together, never separately
  • Walk through edge cases explicitly — the cases where two enumerators would reasonably disagree
  • Pilot with real respondents, review the first submissions the same day, correct before scaling
  • Assign enumerator identifiers so anomalies can be traced to a person and addressed as coaching
Output
  • A team applying the same definition, which is what makes disaggregation trustworthy
STEP 03
↓
Cleaning

A defined sequence rather than an ad hoc pass, so the same decisions are made every round.

The routine
  • Structural checks first: expected submission counts by site, duplicate submissions, incomplete records
  • Logical checks: internal contradictions the form could not catch, outliers reviewed rather than deleted
  • Harmonisation: units, date formats, category labels, location names aligned to the master list
  • Every correction logged with a reason — the log is part of the deliverable, not scratch work
Principle
  • Nothing is deleted silently. A record removed from analysis is recorded as removed, with the rule that removed it
STEP 04
Analysis and Power BI

With a fixed route from form to model, the dashboard rebuilds each round instead of being reconstructed.

Process
  • Cleaned data reshaped into the flat structure the reporting model expects
  • Measures written once against that structure, so a new round is a data refresh rather than a rebuild
  • Disaggregated views built from the fields fixed at form design, not derived afterwards
  • Round-on-round comparison views, which only work because the route did not change
Result
  • Collection, cleaning, analysis and visualisation function as one connected flow
  • Turnaround from field to dashboard measured in days rather than weeks
What breaks when the route is not fixed
  • Each round is cleaned by whoever is available, using slightly different rules — so a change between rounds may be real or may be the cleaning.
  • Definitions drift between enumerator cohorts, and the disaggregation quietly stops meaning the same thing.
  • The dashboard is rebuilt each cycle, which is where most of the effort goes and where most of the errors enter.
