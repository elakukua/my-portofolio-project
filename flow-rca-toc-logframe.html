RCA · Theory of Change · Logframe · MEAL products

What a programme measures is decided before anyone collects anything.

The chain that turns a community problem into a measurable programme. Get it wrong and every dashboard downstream reports the wrong thing accurately.

The design chain — left to right, each output feeds the next

01

Situation analysis

  • Secondary data, previous evaluations, community consultation, stakeholder mapping
  • GESI lens applied from the start
  • Output: one agreed problem statement
02

Root Cause Analysis

  • Participatory problem tree: core problem, effects above, causes below
  • Separate immediate, underlying and root causes — most programmes act at the underlying level
  • Test: a cause removed removes the effect; if you cannot influence it, it is an assumption
  • Output: evidenced causal chain
03

Objective tree

  • Every negative restated as the positive condition it would become
  • Causes become outputs; effects become outcomes
  • Check means–ends logic upward, prune what is out of scope
  • Output: skeleton of the ToC
04

Theory of Change

  • Impact first, then work backwards to outcomes, outputs, activities
  • Assumption written explicitly between every level
  • Evidence attached to each causal link
  • Output: ToC diagram and narrative
05

Logframe

  • Each ToC level becomes a results statement
  • Standard indicator library first; custom only where nothing fits
  • Baseline, target, means of verification, frequency, owner per indicator
  • Where donor indicators diverge from the ToC, map both
  • Output: logframe matrix
06

MEAL products

  • Indicator reference sheets, MEL Plan, Data Management Plan, RASCI matrix
  • Collection tools: Kobo forms, ITT, MTT
  • Baseline & evaluation plan, feedback mechanism, learning agenda
  • Output: a pack a new staff member could pick up and run
