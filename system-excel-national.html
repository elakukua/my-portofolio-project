Excel · Microsoft 365 Online

One shared workbook instead of a folder of versioned copies.

National-level reporting fails in a predictable way: a workbook is emailed out, filled in differently by each team, and returned as eleven files that no longer agree. Moving the workbook online removes the failure mode rather than managing it.

STEP 01
↓
Move collaboration into the workbook

The version problem is not solved by naming conventions. It is solved by there being one file.

Process
  • A single workbook on SharePoint with co-authoring, so teams enter data in place rather than in copies
  • Sheet-level protection: teams edit their own input range and nothing else
  • Data validation on every input cell so a category cannot be invented mid-entry
  • A clearly marked input area separate from the calculation area, so nobody types over a formula
Result
  • The current figure is whatever the workbook says, with no reconciliation of versions needed
STEP 02
↓
Clean and analyse

Structured cleaning inside the same file the data arrives in, so nothing is exported and re-imported.

Process
  • Structured tables rather than ranges, so formulas extend automatically as rows are added
  • Lookup-based harmonisation against master lists for locations, projects and indicator codes
  • Consistency checks: totals against disaggregation, period coverage, missing submissions by team
  • Errors left visible rather than suppressed, so a broken reference is obvious
Output
  • A clean analysis layer that updates as teams enter data
STEP 03
↓
Pivot-based dashboard

Pivot tables are unfashionable and entirely appropriate here — every user already knows how to use them, and the file needs no additional licence.

Process
  • Pivot tables driven from the structured analysis layer, refreshing as the input area fills
  • Slicers for project, period, location and disaggregation, so users answer their own questions
  • A summary sheet designed to be read in under a minute, with the detail sheets behind it
  • Charts built on the pivots rather than on manually maintained ranges
Why not a BI tool here
  • Distribution and access are already solved by Microsoft 365, and the audience can already operate it — a dashboard nobody can open is not a dashboard
STEP 04
MEAL product delivery tracking

The same workbook pattern applied to the MEAL products themselves: which are due, which are delivered, which are late, and who owns each.

What is tracked
  • MEAL products per project: MEL plans, reference sheets, baseline reports, evaluation reports, learning products
  • Due date, responsible person, current status and where the final file lives
  • Overdue items surfaced automatically rather than remembered
  • A rolling view by team, so gaps are visible at management level
Result
  • MEAL product delivery is managed as a pipeline rather than chased individually
What this replaces
  • Eleven versions of one workbook. Consolidation used to be the job; now it is not a job.
  • Verbal status updates on MEAL products. Replaced by a tracker anyone can open before the meeting.
  • Reformatting before every report. The summary sheet is already the report format.
