Beneficiary tracking that is current, not compiled.

Most beneficiary tracking is a compilation exercise — collect workbooks, merge them, and the number is already stale by the time it is read. This replaces that cycle with a pipeline.

The pipeline — runs continuously, no compilation step

01Define the record
02Intake form
03BigQuery
04Looker Studio
01

Define the record

  • Who counts as a beneficiary per project type: direct, indirect, participant, reached
  • Disaggregation the logframe and donor both require: sex, age band, disability, location
  • A unique identifier convention that works across projects without exposing personal data
  • Consent wording and data protection agreed before any collection
02

Intake form

  • One form for many projects; a project field routes the record
  • Required fields, response ranges and controlled dropdowns instead of free text
  • Conditional logic so enumerators see only relevant questions
  • Location from a fixed list, so it joins cleanly downstream
03

BigQuery

  • Raw responses land untouched in staging — the original is never overwritten
  • Transformation handles typing, dates, category harmonisation, identifier construction
  • Deduplication flags rather than silently deletes, so a person decides
  • One clean table is the only object the dashboard reads
04

Looker Studio

  • Cumulative and period reach against target, by project and location
  • Full disaggregation views, because disaggregation was fixed at step one
  • A data quality panel: flagged duplicates, missing disaggregation, submission gaps by site
  • Tracking becomes a question you ask, not a task someone performs
